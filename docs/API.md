# ShelfSync REST API

This is the contract between the ShelfSync web app and a backend built on
[server/schema.sql](../server/schema.sql).

**Status.** The current release runs without a server: the same operations are
carried out in the browser by the functions in
[src/domain/actions.ts](../src/domain/actions.ts) and
[src/domain/auth.ts](../src/domain/auth.ts), and the data is kept in
`localStorage`. Each endpoint below names the function that implements its rules
today, so a server can be written against this document and the app switched
over by replacing [src/context/LibraryContext.tsx](../src/context/LibraryContext.tsx)
and [src/context/AuthContext.tsx](../src/context/AuthContext.tsx). No endpoint
in this document is deployed yet.

## Conventions

| | |
|---|---|
| Base URL | `/api` |
| Format | JSON request and response bodies, `Content-Type: application/json` |
| Field names | camelCase, exactly as in [src/types/index.ts](../src/types/index.ts) |
| Dates | `YYYY-MM-DD`, in the library's local time zone |
| Money | whole rupees, as integers |
| Ids | generated by the server: `BK-001`, `M-0001`, `TXN-0001`, `RSV-0001`, `FIN-0001`, `PAY-0001`, `DMG-001`, `CAT-01` |

### Authentication

`POST /auth/login` returns a JWT. Send it on every other request:

```
Authorization: Bearer <token>
```

The token carries `sub` (user id), `role` (`admin` or `member`) and, for
members, `memberId`.

### Roles

| Role | Access |
|---|---|
| `admin` | Everything. |
| `member` | Read the catalog; read and act on **their own** loans, reservations, fines, notifications and profile. A member asking for another member's records gets `403`. |

The permission names used below are the ones in
[src/lib/permissions.ts](../src/lib/permissions.ts).

### Errors

```json
{ "error": { "code": "RULE_VIOLATION", "message": "No copies are available to issue." } }
```

`message` is written for the end user and is shown as-is in the app.

| Status | Code | When |
|---|---|---|
| 400 | `VALIDATION` | A field is missing or malformed. |
| 401 | `UNAUTHENTICATED` | Missing, invalid or expired token; wrong credentials. |
| 403 | `FORBIDDEN` | The role lacks the permission, or a member is reaching for someone else's data. |
| 404 | `NOT_FOUND` | No record with that id. |
| 409 | `RULE_VIOLATION` | The request is well-formed but a business rule forbids it. |

### Lists

List endpoints accept `page` (default 1), `pageSize` (default 25, maximum 100),
`sort` (a field name, prefix `-` for descending) and `q` (free-text search), and
return:

```json
{ "items": [], "page": 1, "pageSize": 25, "total": 0 }
```

## Auth

| Method | Path | Access | Purpose |
|---|---|---|---|
| POST | `/auth/login` | public | Sign in with email or member id. |
| POST | `/auth/register` | public | Create a member account and sign in. |
| GET | `/auth/me` | signed in | The current user. |
| POST | `/auth/change-password` | signed in | Replace your own password. `changePassword` |
| POST | `/auth/reset-password` | public | Reset a member's password by confirming details on their record. `resetPasswordWithIdentity` |
| POST | `/members/:id/temporary-password` | `members:manage` | The desk resets a member's password. `issueTemporaryPassword` |

```http
POST /api/auth/login
{ "identifier": "member@shelfsync.demo", "password": "…" }

200
{
  "token": "eyJhbGciOi…",
  "user": { "id": "M-0001", "name": "…", "email": "…", "role": "member", "memberId": "M-0001", "title": "Student · M-0001" }
}
```

`POST /auth/register` takes `name`, `email`, `phone`, `department`, `type` and
`password` (at least 8 characters) and returns the same shape with `201`.
Passwords are stored only as a salted, stretched hash in `users.password_hash`.

Every failed sign-in returns the same `401` message, whether the account is
unknown or the password is wrong, so the endpoint does not reveal which
accounts exist.

- `POST /auth/change-password` takes `{ "current", "next" }`. The current password must be right and the new one different.
- `POST /auth/reset-password` takes `{ "memberId", "email", "phone", "password" }`. All three details must match the member's record (phone numbers are compared on their last ten digits); any mismatch returns one generic `409`. This stands in for an emailed reset link, which arrives with Phase 2.
- `POST /members/:id/temporary-password` returns `{ "password": "k7mq-4xpd" }` once. It sets `users.must_change_password`, and `GET /auth/me` reports `mustChangePassword: true` until the member chooses their own.
- A member the desk registers (`POST /members`) is given a temporary password the same way, returned in the response as `temporaryPassword`.

## Catalog

### Books

| Method | Path | Access | Function |
|---|---|---|---|
| GET | `/books` | signed in | — |
| GET | `/books/:id` | signed in | — |
| POST | `/books` | `catalog:manage` | `addBook` |
| PUT | `/books/:id` | `catalog:manage` | `updateBook` |
| DELETE | `/books/:id` | `catalog:manage` | `deleteBook` |
| POST | `/books/import` | `catalog:manage` | `importBooks` |

`GET /books` filters: `q` (title, author, ISBN, publisher, category, subject, description),
`category`, `availability` (`available`, `low_stock`, `checked_out`, `reserved`,
`damaged`), `status` (`active`, `archived`).

Every book is returned with its live inventory, read from the `book_inventory`
view:

```json
{
  "id": "BK-001", "title": "…", "author": "…", "isbn": "…", "publisher": "…", "year": 2019,
  "category": "Computer Science", "subject": "…", "description": "…", "shelf": "B-07-3",
  "totalCopies": 4, "status": "active", "addedOn": "2026-01-12",
  "inventory": { "total": 4, "available": 1, "issued": 2, "reserved": 1, "damaged": 0, "state": "low_stock" }
}
```

`GET /books/:id` also returns `queue` (open reservations in service order) and
`damage` (the title's damage reports). Members see queue entries without the
other members' names.

Rules:

- `title`, `author` and `isbn` are required; `isbn` is unique; `totalCopies` is a whole number ≥ 0.
- `totalCopies` cannot be lowered below the copies currently issued, held or under repair.
- A book with copies on loan cannot be deleted. Deleting a book cancels its open reservations.
- `POST /books/import` takes `{ "books": [ … ] }` and returns `{ "added": 12, "skipped": 2 }`; rows that fail validation are skipped, not fatal.

## Circulation

| Method | Path | Access | Function |
|---|---|---|---|
| GET | `/loans` | `circulation:manage`; members get their own | — |
| GET | `/loans/issue-check?memberId=&bookId=` | `circulation:manage` | `issueBlocker` |
| POST | `/loans` | `circulation:manage` | `issueBook` |
| GET | `/loans/:id/renew-check` | `circulation:manage`; members for their own loan | `renewBlocker` |
| POST | `/loans/:id/renew` | `circulation:manage`; members for their own loan | `renewLoan` |
| POST | `/loans/:id/return` | `circulation:manage` | `returnBook` |

`GET /loans` filters: `memberId`, `bookId`, `status` (`active`, `overdue`,
`returned`), `from`, `to`.

### Issue a book

```http
POST /api/loans
{ "memberId": "M-0004", "bookId": "BK-012" }

201
{ "loan": { "id": "TXN-0199", "bookId": "BK-012", "memberId": "M-0004", "issueDate": "2026-10-04", "dueDate": "2026-10-18" } }
```

The due date is the issue date plus `settings.loanPeriodDays`. The request is
refused with `409` when:

- the member is suspended;
- the title is archived;
- the member already has a copy of this title;
- the member has reached `settings.maxLoansPerMember`;
- no copy is available — unless a copy is being held for this member (a `ready` reservation).

Issuing closes the member's open reservation for the title as `fulfilled` and
notifies the member. `GET /loans/issue-check` returns `{ "blocker": null }` or
the reason as text, so the desk sees the problem before submitting.

### Renew a loan

`POST /loans/:id/renew` moves the due date on by `settings.loanPeriodDays`,
counted from the current due date, and adds one to the loan's `renewals`. It is
refused with `409` when:

- renewals are switched off (`settings.maxRenewals` is 0);
- the loan has already been renewed `settings.maxRenewals` times;
- the loan is overdue;
- the member is suspended;
- another member is waiting in the queue for the title.

`GET /loans/:id/renew-check` returns `{ "blocker": null }` or the reason as text.

### Return a book

```http
POST /api/loans/TXN-0142/return
{
  "damage": {
    "type": "Water damage", "severity": "High", "description": "Pages 40–80 warped",
    "repairCost": 250, "images": [], "chargeMember": true
  }
}

200
{
  "loan": { "id": "TXN-0142", "returnDate": "2026-10-04", "…": "…" },
  "fine": { "id": "FIN-0035", "reason": "overdue", "overdueDays": 4, "rate": 5, "amount": 20, "paid": 0 },
  "damageFine": { "id": "FIN-0036", "reason": "damage", "amount": 250, "paid": 0 },
  "nextReservation": { "id": "RSV-0013", "memberId": "M-0009", "status": "waiting" }
}
```

`damage` is optional; send an empty body for a clean return. In one
transaction the server:

1. Sets the return date.
2. Raises an overdue fine when the book is late:
   `overdueDays = max(0, returnDate − dueDate − settings.graceDays)` and
   `amount = overdueDays × settings.fineRatePerDay`. The rate is copied onto the
   fine, so later changes to the setting do not alter it.
3. When `damage` is present, creates a damage report (the copy is withdrawn from
   circulation for `High` and `Critical` severity) and, if `chargeMember` is true
   and `repairCost` > 0, a second fine with `reason: "damage"`.
4. Notifies the member, and adds a staff notification if someone is waiting for
   the title.

`fine`, `damageFine` and `nextReservation` are `null` when they do not apply.

## Reservations

| Method | Path | Access | Function |
|---|---|---|---|
| GET | `/reservations` | `reservations:manage`; members get their own | — |
| POST | `/reservations` | `reservations:manage`, or `reservations:self` for oneself | `createReservation` |
| POST | `/books/:id/notify-next` | `reservations:manage` | `notifyNextInQueue` |
| PATCH | `/reservations/:id` | `reservations:manage`; members may cancel their own | `closeReservation` |

Open reservations are returned with `position` (1-based, from the
`reservation_queue` view) and `estimatedAvailability`.

Rules:

- `POST /reservations` takes `{ "memberId", "bookId" }`. If a copy is free and nobody is queued, the reservation is created as `ready` (a pickup request); otherwise it joins the back of the queue as `waiting`.
- Refused with `409` when the member is suspended, the title is archived, the member already has an open reservation for the title, or currently has it on loan.
- `notify-next` sets a free copy aside for the first waiting member (`waiting` → `ready`, `readyOn` = today) and notifies them. Refused when nobody is waiting or no copy is free.
- `PATCH` takes `{ "status": "cancelled" | "expired" }`; only open reservations can be closed. Members may only send `cancelled`.
- A `ready` reservation not collected within `settings.holdDays` is expired by the scheduled job below.

## Fines and payments

| Method | Path | Access | Function |
|---|---|---|---|
| GET | `/fines` | `fines:manage`; members get their own | — |
| GET | `/payments` | `fines:manage`; members get their own | — |
| POST | `/fines/:id/payments` | `fines:manage` | `recordPayment` |

Fines are returned with `balance` and `status` (`pending`, `partial`, `paid`)
from the `fine_ledger` view. `GET /fines` filters: `memberId`, `status`,
`reason`.

```http
POST /api/fines/FIN-0035/payments
{ "amount": 20, "method": "UPI", "reference": "UPI-88213", "date": "2026-10-04" }

201
{ "payment": { "id": "PAY-0029", "fineId": "FIN-0035", "memberId": "M-0004", "amount": 20, "method": "UPI", "reference": "UPI-88213", "date": "2026-10-04" } }
```

`amount` must be greater than zero and no more than the balance; part payments
are allowed. `method` is `Cash`, `UPI`, `Card` or `Bank Transfer`. The payment
row and the fine's `paid` total are written together, and the member is
notified.

Loans that are still out and already late have no fine row yet. `GET /loans`
returns `accruingFine` for them — what the fine would be if the book came back
today.

## Damage reports

| Method | Path | Access | Function |
|---|---|---|---|
| GET | `/damage` | `damage:manage` | — |
| GET | `/damage/:id` | `damage:manage` | — |
| POST | `/damage` | `damage:manage` | `addDamageReport` |
| PATCH | `/damage/:id` | `damage:manage` | `updateDamageStatus` |

`POST /damage` takes `bookId`, optional `memberId` and `loanId`, `date`, `type`,
`severity`, `description` (required), `repairCost`, `images`, `notes`. Reports
start as `reported`; `High` and `Critical` reports withdraw one copy until the
report is `resolved`.

`PATCH /damage/:id` takes `{ "status", "note", "repairCost"? }` and appends an
entry to the report's `timeline`. Statuses: `reported`, `under_review`,
`under_repair`, `resolved`.

Images are sent as `multipart/form-data` to `POST /damage/:id/images` and
returned as URLs.

## Scheduled job

Once a day the server runs `runSystemSweep`. The browser build runs the same
sweep each time the app loads.

- **Holds.** Every `ready` reservation whose `readyOn` is more than `settings.holdDays` ago becomes `expired`, which returns the held copy to the shelf.
- **Due-date reminders.** A member is notified when a loan is due within `settings.reminderDays`.
- **Overdue notices.** A member is notified once when a loan becomes overdue.

Each reminder is stored with a `dedupe_key` (the loan and its due date), so
running the job again sends nothing twice, and a renewed loan is reminded again
when its new due date comes round.

## Backup

| Method | Path | Access | Purpose |
|---|---|---|---|
| GET | `/backup` | `settings:manage` | Download the whole library as one JSON file. |
| POST | `/backup/restore` | `settings:manage` | Replace the library with a backup file. |

The file is `{ "app": "shelfsync", "format": 1, "exportedOn": "…", "db": { … } }`.
